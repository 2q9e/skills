# Evidence-first research

Research the proposition the user needs to establish, then identify what the available evidence actually supports. Prefer current, inspectable sources over built-in model knowledge, which may be stale and cannot itself be verified by the reader. Do not search merely for sources that agree with a desired conclusion. Respect source, date, geography, language, and format constraints. Never imply that a source was opened or verified if the current environment could not retrieve it.

## 1. Define the evidence need

Before searching, restate the claim internally as a checkable proposition. Identify its subject, relationship, place, timeframe, population or industry, magnitude, causal wording, and requested publication type. Split compound claims into components. Note hard requirements (for example, “government sources only” or “no blogs”) separately from preferences. Do not relax hard requirements silently; report a genuine evidence gap if suitable sources cannot be found within them.

Decide whether the user needs an original record, data, research, reporting, a quotation, a comparison, or a concise explanation. Search depth should match the stakes and difficulty: a straightforward fact needs little; consequential, disputed, or complex claims merit corroboration.

## 2. Search for the best available evidence

Use the search, browsing, academic, document, and file tools actually available in the host. Discover their syntax and limits instead of assuming one provider’s operators work everywhere. For factual research, ground conclusions in sources you retrieved or material the user supplied; use built-in knowledge only to generate search terms or provide clearly labeled context, never as a substitute for evidence when retrieval is available. Prioritize original and authoritative sources, and check publication/update dates and the date of underlying data when recency matters. If browsing or retrieval is unavailable, say that current verification was not possible, separate any provisional built-in context from verified evidence, and offer search terms or assess only material the user supplied.

Build a small set of concept variants: synonyms, alternate technical terms, names of relevant institutions or researchers, geography, and dates. Search for original studies, official datasets and reports, primary records, and the specific document behind a secondary claim. Useful tactics where supported include quoted phrases, domain filters, file-type filters, DOI/title searches, backward citation tracing, and forward searches for newer work. Search specialist databases when available. If early results are weak, vary the query or source class rather than repeating it.

Open promising sources and inspect their substantive text, tables, figures, notes, or relevant PDF pages. A result title, abstract, snippet, search summary, or another site's description is a lead, not verification. Continue while a materially stronger source is reasonably likely; stop when a suitable source is found, additional search has sharply diminishing value, or a practical access limit is reached. Do not claim exhaustive coverage without grounds.

## 3. Classify the actual publication

For each serious candidate, identify the author, publisher, publication and update dates, document type, evidence role, review or editorial process, method, relevant expertise, interests or conflicts, and accessibility. Classify the document itself, not its domain, URL path, branding, or title alone. Separate these dimensions:

- **Format:** paper, report, release, article, newsletter, blog post, dataset, documentation, and so on.
- **Publisher:** government body, journal, newsroom, university, company, NGO, individual, or other institution.
- **Evidence role:** original evidence, independent reporting, synthesis, commentary, promotion, or documentation.
- **Quality for this claim:** directness, methods, accuracy, currency, independence, and verifiability.

Use these distinctions as applicable:

| Type | What to check |
| --- | --- |
| Peer-reviewed paper | Verify the journal and review status; assess design, limitations, date, and subsequent evidence. Peer review is not a guarantee of correctness. |
| Preprint | Research manuscript; determine whether it has since been peer-reviewed or revised. |
| Systematic review / meta-analysis | Search strategy, inclusion criteria, study quality, heterogeneity, and date. |
| Government research report / statistical release | Agency, authorship, methods, definitions, revisions, scope, and whether findings are research or official statistics. |
| Technical report / official documentation | Producing organization, version, methods or specification, and authority for the technical question. |
| Institutional research report | Research design, author expertise, funding, institutional interests, and data access. |
| News article / investigation / analysis | Distinguish original reporting and documents/interviews from analysis or summaries; check named authors, editorial standards, sourcing, and corrections. |
| Newsletter | A periodic delivery format, not an evidence-quality category. Determine whether it summarizes others, offers commentary, or reports original evidence. |
| Blog post | A publishing format that may contain expertise, data, reporting, opinion, or unsupported claims. Read and assess the actual post. |
| Opinion / editorial | Treat the argument as viewpoint; verify factual premises independently. |
| Press release | Interested-party statement. Trace claims and data to the underlying record and seek independent corroboration. |
| Corporate / industry report | May offer useful primary data; inspect methods, sponsorship, selective framing, and conflicts. |
| NGO / advocacy publication | Assess evidence and methods alongside the organization's mission and interests. |
| Primary record / dataset | Check provenance, completeness, definitions, version, and what the record can establish. |
| Secondary summary | Follow references to the original evidence where possible; do not treat repetition as independent corroboration. |

A government source, famous outlet, academic journal, newsletter, company, or blog is not automatically reliable or unreliable. Publication type is not a substitute for document-level appraisal.

## 4. Verify claim-to-source support

For every source considered for citation:

1. Retrieve the original source or the closest accessible primary record.
2. Find the exact passage, table, figure, dataset field, or section relevant to the claim.
3. Read enough surrounding context to preserve qualifications and scope.
4. Verify author/publisher and publication date; check for corrections, newer editions, and newer underlying research when currency matters.
5. Check numbers for units, currency, denominator, geography, timeframe, baseline, and whether they are observed, estimated, modeled, or projected.
6. Record the source's limitations and any relevant conflicts.
7. Assign a qualitative support label:
   - **Direct:** explicitly establishes the material proposition.
   - **Partial:** supports only some components.
   - **Indirect:** relevant context requiring inference.
   - **Contradictory:** weighs against the proposition.
   - **No support:** related topic but no evidence for the claim.
   - **Unverified:** relevant content could not be accessed or checked.

Keep relevance and credibility separate. Rank candidates by fit to user constraints, directness, evidence and method quality, credibility, geographic and temporal fit, independence, and inspectability. Use concise judgments such as “strong direct evidence,” “credible but partial,” or “indirect context”; do not invent precise numeric credibility scores. A credible source can be irrelevant, and a relevant headline does not prove the contents are sound.

Watch for causal claims based only on correlation, cherry-picked figures, missing methods, selective quotations, recycled press releases, circular citations, predatory journals, sponsored content, undisclosed interests, estimates presented as outcomes, revenue confused with profit or economic impact, local results generalized too widely, and old findings presented as current. For consequential or disputed claims, seek independent corroboration when practical. Trace repeated coverage to its common origin. When sources disagree, compare definitions, dates, methods, geography, revisions, interests, and genuine uncertainty; explain material disagreement instead of hiding it.

### Fast-moving stories and allegations

For breaking, developing, disputed, or high-stakes news, make evidence status explicit with a short **Confirmed / Reported / Unknown** breakdown when useful:

- **Confirmed:** State only what is established by inspected records or sufficiently corroborated evidence. Attribute official statements precisely: an announcement can confirm what an organization announced or what its spokesperson says; it does not automatically verify every underlying claim in that statement.
- **Reported, not independently established:** Attribute the claim to the named outlet or source. Describe the evidence it reports (for example, on-the-record interviews, documents, named or anonymous sources, or data) and its limits. Do not restate allegations as facts or strengthen a source's wording.
- **Unknown / not established:** Identify what remains under investigation, unverified, undisclosed, or unresolved. Do not infer that an allegation is true from an investigation, or infer that it is false from a denial or lack of public evidence.

For the strongest source, explain why it carries the most weight for the specific claim, what evidence it actually presents, and what it cannot establish. Check the source's latest update, the event date, and later corrections or statements; label the answer with an “as of” date when developments may change it. Do not force this format onto routine, settled questions.

## 5. Cite and report precisely

Use APA 7th edition author-date in-text citations for sourced factual claims and include a matching **References** list with retrievable links or DOIs. Put citations next to the claims they support. Format each reference using the actual work type and verified metadata (author, date, title, source); do not guess missing details. Prefer a stable link to the original document, study, official record, or dataset, not a homepage or secondary retelling. Identify publication type and relevant page, section, table, or dataset location when available. Use the host's native citation mechanism if required, while still supplying APA-style author-date references when the user requests APA. Never invent URLs, dates, page numbers, source identifiers, or references.

For every source cited, explain its specific contribution: which claim(s) it supports, what evidence it provides and where that evidence appears, and any material limitation. A citation list without a claim-to-source explanation is insufficient. Keep this mapping concise (for example, a short “Source contributions” list or table); cite each factual claim in APA author-date style beside the claim and provide its complete matching APA reference.

For a requested quotation, copy a short passage exactly from inspected source text and provide its location. If exact wording cannot be checked, say so; do not reconstruct a quote from memory or a snippet. Clearly distinguish quotation, paraphrase, summary, interpretation, and inference. Preserve qualifications in paraphrases and respect applicable quotation limits.

### Required per-message citations and provenance

Once this skill is invoked, keep these citation and provenance rules active for the entire current conversation, including follow-up answers, corrections, and status messages. Every response must include APA citations and source contributions for evidence it uses, then end with a compact **Evidence provenance** note. Reuse previously retrieved sources when they remain relevant and identify what each one supports in that response. Include a matching References entry for every source cited. If a response adds or relies on no evidence, say that no new sources were used rather than inventing a citation.

Distinguish:

- **Retrieved sources:** sources actually opened or inspected for this response; cite them in APA in the answer and References list.
- **User-provided material:** uploaded, pasted, or linked material supplied by the user; identify it as such and cite it in APA when enough metadata is available.
- **Built-in knowledge:** state whether it was used. If used, describe it only as background or search guidance, never as retrieved or verified evidence. If not used as evidence, say “Built-in knowledge: not used as evidence.”

Do not imply that a source was retrieved when it was only supplied by the user, or that either was retrieved from an internal knowledge base. If a source type was not used, say “None.” Keep the contribution map and note concise, but do not omit them from brief follow-ups while the skill is active. Place source contributions and References near the end, with Evidence provenance as the final section of every response.

Adapt the answer to the ask:

- **One source:** give the best match, type, exact support and location, why it is credible for this question, and the key limitation; state explicitly what this source helped establish and what it did not.
- **Several sources:** rank a concise shortlist and identify each source's type, evidence role, support level, contribution, and limitation.
- **Quotation or paraphrase:** provide inspected wording or a faithful, clearly labeled paraphrase with location.
- **Source comparison:** compare publication type, directness, evidence/method, currency, independence, and limitations.
- **Developing story or allegations:** separate established facts, attributed reporting, and unresolved questions; explain the strongest source's evidence and limits.
- **Deep research:** synthesize what is well supported, disputed, uncertain, and missing.

If the proposed claim is unsupported, overstated, or contradicted, say which part fails, state the narrowest defensible conclusion, and locate evidence for it where possible. Include meaningful contrary evidence. Truthfulness takes priority over confirmation.

## 6. Portability

This skill requires no particular plugin, MCP server, search engine, database, or citation format. Use equivalent capabilities exposed by the host and do not claim platform features the environment does not provide. The Agent Skills `SKILL.md` convention is shared by a growing set of tools, but skill discovery paths, invocation, automatic loading, and available research tools vary. Follow the client’s current documentation for installation and invocation; do not promise that one directory or installation method works in every assistant. If only user-provided sources are accessible, label the scope accordingly.
